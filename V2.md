# Blender MCP V2 development release

This branch preserves the MCP address and the `render_preview` and `preview_status` tools. A deployment with no `BLENDER_V2_DIR` specified exposes only the legacy tools. V2.0 production promotion requires the acceptance gates in the project specification.

## Runtime and storage

- Legacy preview uses Debian Blender 4.3.2. Production tasks use Blender 5.3.0, verified against the official SHA-256 at build time. The Linux container includes FFmpeg and Open CASCADE.
- Mount one persistent volume at `/data`. Run one service replica with `BLENDER_V2_DIR=/data/blender`. Keep that volume across deploys. A volume lock prevents concurrent schedulers on the same data directory.
- Set `BLENDER_ACCESS_ID` to the MCP URL credential and `BLENDER_V2_SIGNING_KEY` to a separate randomly generated secret. Set `BLENDER_V2_PRINCIPAL` if the installation needs a named owner. One deployment serves one trusted owner.
- Set `BLENDER_PUBLIC_URL` only when the provider's domain variables cannot supply the public HTTPS origin. Health check is `/health`. Default port is 10000.
- For resource tuning, set `BLENDER_V2_MEMORY_MIB`, `BLENDER_V2_JOB_DISK_MIB`, and `BLENDER_V2_UPLOAD_MIB` within the actual worker and storage ceilings. The defaults are 1024 MiB of job RSS, 192 MiB of job output and 32 MiB per upload. Combined job inputs are capped at 64 MiB. The server dispatches one production job at a time.
- Store contains a SQLite catalog, original hashed assets, version files, and job outputs. All production artifacts are kept until an authorized operator removes them. The original previews still follow their existing temporary retention. Take a storage snapshot or use `export_project` before migrations. Copy the database using SQLite's backup API if taking a manual backup while the service is running.
- The Docker entrypoint prepares the volume directory and drops privileges. Production execution requires functional Linux user, PID and network namespaces and Bubblewrap. Confirm with a real `blender_info` task before admitting customer files.

## Tools

All production tools require the existing authenticated MCP URL credential. Generate a new UUID for each intended write and reuse the UUID for an identical retry.

| Tools | Purpose |
| --- | --- |
| `create_project`, `list_projects` | Create or find an owner-scoped project. |
| `upload_asset`, `list_assets`, `get_asset` | Obtain a signed browser upload form or raw PUT URL, list immutable assets, and download an original. Use project-relative paths for model dependencies. |
| `import_model`, `inspect_model` | Read a model under isolation, check its structure and dependencies, and save an editable project. STEP conversion uses Open CASCADE's XCAF reader and a tessellated GLB intermediary. |
| `run_script`, `open_project` | Save a new immutable version from an approved recipe, or list and reopen versions. `product_showcase` builds a camera and presentation lighting. `edit_objects` supports targeted transforms, parent relationships, constraints, keyframes, material overrides, HDRI, grouping, lights, camera edits and cuts, and frame markers. |
| `render_image`, `render_animation`, `extract_frames` | Render an existing version using typed renderer settings. Animated output includes numbered PNGs and an H.264 MP4 assembled with FFmpeg. |
| `blender_info` | Run a live runtime probe and optionally render one test frame with a specified engine. |
| `task_status`, `cancel_task`, `retry_task` | Query persisted status and frame counts, cancel, or retry an unsuccessful task. |
| `review_image`, `get_output`, `export_project` | Read PNG content into GPT, issue signed artifact links, and create a backup ZIP. |

Blender uses the scene's units and existing object names. Treat the report's world-space bounding-box overlaps as candidates for review. Confirm part identities and motion directions from authorized project records before asserting assembly behavior. For Blender files with linked libraries, make the library data local before upload. Supply external image files in the same project and submit their asset IDs with the import.

Example workflow: create a project, issue an upload link for the model, import using the returned asset ID, read the model report with `get_output`, run `product_showcase`, render frames 1–48 at 24 fps and 854 × 480, then open `preview.mp4` and the selected engineer-editable version. Use `edit_objects` against a saved version and `extract_frames` to inspect a specific change.

## Security

- The MCP URL contains a bearer credential. Keep it private and rotate it if shared. Put secrets in the host's environment store and keep platform logs containing request URLs restricted.
- File URLs are short-lived HMAC capabilities scoped to an owner, project and exact transfer operation. A task or asset ID alone grants no direct access. V1 downloads also use signed URLs when V2 is enabled.
- The worker receives a cleared environment, fresh namespaces, only the current task's inputs mounted read-only, and a dedicated writable output directory. Authority remains in the MCP server. Blender auto-execution is disabled. The service exposes two reviewed recipe families and rejects arbitrary Python strings.
- Enforced task limits cover wall clock time, CPU time, virtual memory, sampled process-group RSS and artifact size. Cancellation terminates the process group. Actual aggregate storage capacity and platform process isolation still need staging verification. Maintain a quota and storage alerts on a production deployment.

## Deploy and rollback

Deploy this branch to a separate test service and volume. Confirm the actual runtime with `blender_info`, then verify all relevant gates in `V2-acceptance.md`. Mount a persistent test volume and verify reconstruction after restarting the service.

The protected production rollback baseline is Git commit `4118aa092b58b90e36725383ff90cd6bab9323a9`. Railway baseline deployment is `355037a1-83bb-4f03-aeb0-bd8c0fd16e70`. Keep production service source and address as-is while testing. If a later approved rollout must be reversed, restore the prior deployment and retain the V2 volume for recovery and audit. Refresh the ChatGPT plugin's tool list only after verified promotion.

## Reproduce the core acceptance

With a private model and an active isolated test service, set `V2_TEST_ORIGIN`, `V2_TEST_ACCESS`, `V2_TEST_MODEL` and `V2_TEST_OUTPUT` in your local environment and run `python tests/acceptance.py`. FFprobe is required on the test client. The fixture is supplied separately and stays outside Git. The script verifies signed file transfer, task idempotency, project scopes, original file hashing, animation media, version history, real review image content, explicit errors and project export.
